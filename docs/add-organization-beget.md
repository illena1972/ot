# Подключение новой организации на Beget

Этот регламент используется для каждой новой организации. Одна установка
приложения обслуживает все организации, но данные и пользователи каждой из них
хранятся в отдельной базе MySQL.

## 1. Подготовить данные клиента

До начала работ определить:

- отображаемое наименование организации;
- короткий код `slug` из латинских строчных букв, цифр и дефисов;
- адрес `<slug>.app.bioclean.ru`;
- короткий код базы MySQL;
- логин первого администратора.

На Beget полное имя пользователя MySQL не должно превышать 16 символов. Для
аккаунта `illena` код после `illena_` должен быть не длиннее 9 символов.

## 2. Создать адрес

1. В панели Beget добавить `<slug>.app.bioclean.ru`.
2. Прилинковать адрес к существующему сайту `app.bioclean.ru/public_html`.
3. Перевыпустить бесплатный стандартный сертификат Let's Encrypt, отметив
   основной домен и все используемые поддомены.
4. После выпуска сертификата проверить открытие адреса по HTTPS.

Для нового клиента не создается отдельный сайт или новая копия приложения.

## 3. Создать пустую базу

1. В разделе MySQL панели Beget создать базу `illena_<db_code>`.
2. Сгенерировать отдельный надежный пароль и сохранить его в менеджере паролей.
3. Оставить доступ только с `localhost`.
4. Не передавать пароль в переписке и не добавлять его в Git.

## 4. Добавить подключение в `.env`

В Docker-окружении перейти в каталог приложения и сохранить резервную копию
текущих настроек:

```bash
cd ~/app.bioclean.ru
cp .env .env.before-new-organization
chmod 600 .env.before-new-organization
nano .env
```

Добавить блок, где `CLIENT_SLUG` — код организации в верхнем регистре, а дефисы
заменены подчеркиваниями:

```text
BIOCLEAN_ORGANIZATION_CLIENT_SLUG_DATABASE_USER=illena_dbcode
BIOCLEAN_ORGANIZATION_CLIENT_SLUG_DATABASE_PASSWORD=private-password
BIOCLEAN_ORGANIZATION_CLIENT_SLUG_DATABASE_HOST=localhost
BIOCLEAN_ORGANIZATION_CLIENT_SLUG_DATABASE_PORT=3306
```

Имя базы хранится в центральном реестре и передается команде на следующем шаге.

## 5. Подготовить организацию

В активированном виртуальном окружении выполнить:

```bash
python manage.py provision_organization \
  --name "Наименование организации" \
  --slug client-slug \
  --database-name illena_dbcode \
  --domain client-slug.app.bioclean.ru
```

Команда проверяет подключение, создает запись в центральном реестре и применяет
все миграции к новой пустой базе. Если подключение или миграция завершается
ошибкой, запись из центрального реестра удаляется автоматически.

## 6. Создать первого администратора

```bash
python manage.py create_organization_admin \
  --organization client-slug \
  --username admin-login
```

Пароль вводится дважды и не отображается в терминале.

## 7. Перезапустить и проверить

```bash
touch ~/app.bioclean.ru/tmp/restart.txt
```

Проверить:

1. На странице входа открывается нужный адрес.
2. Новый администратор входит в систему.
3. Списки сотрудников, склада и выдач пусты.
4. Учетная запись другой организации не подходит.
5. Данные существующих организаций не изменились.

После успешной проверки удалить временную копию настроек:

```bash
rm ~/app.bioclean.ru/.env.before-new-organization
```

## 8. Зафиксировать подключение

В закрытом реестре владельца системы сохранить:

- наименование, slug и адрес организации;
- имя базы MySQL;
- имя администратора;
- дату подключения;
- место хранения пароля базы и пароля администратора.

Сами пароли в этот регламент и репозиторий не записываются.
