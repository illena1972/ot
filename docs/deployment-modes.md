# Единая сборка для SaaS и локальной установки

Проект выпускается из одной ветки и одного Git-тега. Отдельные ветки для SaaS
и локальной установки не создаются.

## Профили

| Профиль | BIOCLEAN_ENV | Запуск | Транспорт |
| --- | --- | --- | --- |
| Разработка | `dev` | Django development server | HTTP |
| Локальный клиент | `local` | Waitress | HTTP в локальной сети |
| Хостинг | `prod` | Passenger | HTTPS |

В режимах `local` и `prod` используется MySQL, центральная platform-база и
отдельная рабочая база каждой организации. `BIOCLEAN_MULTI_TENANT=1` остается
включенным в обоих вариантах.

## Правило версий

Версия приложения одинакова для всех установок. Из одного релиза используются:

- `config/local.env.example` и `deployment/local/*` для локального клиента;
- `config/hosting.env.example` и `deployment/server/*` для хостинга.

Файл `.env`, базы данных и резервные копии никогда не входят в релиз.

## Порядок выпуска

1. Собрать frontend и универсальный релиз.
2. Выполнить автоматические проверки.
3. Проверить релиз на тестовой организации.
4. Сделать резервные копии баз целевой установки.
5. Обновить SaaS и выполнить `migrate_all_organizations`.
6. Обновить локальную установку тем же релизом.
7. Выполнить ручной тест для каждого варианта развертывания.

## Независимость данных

Копии одной организации на локальном сервере и на хостинге не синхронизируются.
Для реального учета должна использоваться только одна из них. Облачная копия
First является тестовой и не должна получать новые рабочие данные.
