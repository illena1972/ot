# Приостановка доступа организации

Механизм используется, если закончился пробный или оплаченный период. Он
блокирует весь адрес организации, но не удаляет ее базу, пользователей и
документы. Ежедневное резервное копирование продолжает включать неактивные
организации.

## Приостановить доступ

В каталоге приложения с активированным виртуальным окружением выполнить:

```bash
python manage.py set_organization_access \
  --organization client-slug \
  --disable
```

После команды все запросы по адресу организации получают ответ `403` с
сообщением о приостановленном доступе. Перезапуск приложения не требуется.

## Возобновить доступ

После подтверждения оплаты выполнить:

```bash
python manage.py set_organization_access \
  --organization client-slug \
  --enable
```

Пользователи снова смогут войти с прежними логинами и паролями. Все данные
останутся в том же состоянии, в котором были до приостановки.

## Проверка состояния

```bash
python manage.py shell -c "from organizations.models import Organization; print(*Organization.objects.using('platform').values('name', 'slug', 'is_active'), sep='\n')"
```

Значение `False` означает, что доступ приостановлен; `True` — что организация
активна.

## Правила безопасности

- Перед первой блокировкой проверить свежую резервную копию базы клиента.
- Не удалять организацию, домен, базу MySQL или строки подключения из `.env`.
- Не отключать отдельных пользователей вместо организации: это сложнее
  восстановить и не блокирует новые учетные записи.
- После возобновления проверить вход и отображение названия организации.

## Просмотр активности

После установки журнала активности можно посмотреть дни и время работы
пользователей за последние 30 дней:

```bash
python manage.py organization_activity --organization client-slug
```

Для произвольного периода:

```bash
python manage.py organization_activity \
  --organization client-slug \
  --date-from 2026-10-01 \
  --date-to 2026-10-31
```

В журнал записываются только имя пользователя, дата, первая и последняя
активность. Адреса страниц, содержимое действий, пароли и IP-адреса не
сохраняются. Активность фиксируется не чаще одного раза в пять минут для одной
пользовательской сессии.
