# Локальная установка

Локальная установка использует тот же код и ту же схему изоляции организаций,
что и SaaS. Для одного клиента создаются две базы MySQL:

- центральная база реестра организаций;
- отдельная рабочая база клиента.

## Первоначальная настройка

1. Назначить компьютеру-серверу постоянный IP-адрес в локальной сети.
2. Установить Python 3.12 и MySQL 8.
3. Создать две базы MySQL и отдельного пользователя приложения.
4. Создать `venv` и выполнить `pip install -r requirements.txt`.
5. Скопировать `config/local.env.example` в `.env` в корне приложения.
6. Заполнить секретный ключ, реквизиты MySQL и локальный IP-адрес.
7. Выполнить `python manage.py migrate organizations --database=platform`.
8. Подготовить организацию командой `provision_organization`. В параметре
   `--domain` указать адрес, который пользователи вводят в браузере, например
   `192.168.1.10`.
9. Создать первого администратора командой `create_organization_admin`.
10. Выполнить `python manage.py collectstatic --noinput`.
11. Запустить `deployment/local/start.ps1`.

Пользователи открывают приложение по адресу вида
`http://192.168.1.10:8000`.

## Обновление

1. Остановить локальную службу приложения.
2. Сделать резервные копии обеих баз MySQL и текущей папки приложения.
3. Заменить файлы программы содержимым нового релиза. Не заменять `.env`.
4. Запустить `deployment/local/update.ps1`.
5. Перезапустить службу и выполнить ручную проверку.

Скрипт обновления устанавливает зависимости, проверяет конфигурацию, применяет
миграции ко всем базам и собирает статические файлы. Резервную копию он не
создает, потому что реквизиты и способ резервного копирования зависят от
конкретной установки.

Для ежедневного резервного копирования запланировать запуск
`deployment/local/backup.ps1` через Планировщик заданий Windows. Скрипт создает
копии центральной и всех клиентских баз; подробности приведены в
`DATABASE_BACKUPS.md`.
